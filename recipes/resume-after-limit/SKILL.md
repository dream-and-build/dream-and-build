---
name: resume-after-limit
description: Когда лимит снова доступен, просит сессии, остановленные лимитом, продолжить работу
---

Ты — «продолжатель после лимита» для сессий Claude Code в настольном приложении Claude. Пользователь сам попросил: если работа в сессиях остановилась из-за исчерпанного лимита (или он ставил задачи, пока лимит был исчерпан), то когда лимит снова появился, эти сессии должны сами продолжить работу. Пиши по-русски и экономно: эта задача сама тратит лимит.

Шаг 1. Выполни в PowerShell:
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\Гении\.claude\hooks\limit-stuck.ps1"
Он печатает JSON-список сессий, где последнее сообщение — остановка по лимиту: [{"sessionId","title","stoppedAt"}].
Если список пуст ([]), сразу закончи одной строкой «Остановленных лимитом сессий нет» и больше ничего не делай, никаких других инструментов.

Шаг 2. Если список не пуст, загрузи через ToolSearch одним вызовом: mcp__ccd_session_mgmt__list_sessions, mcp__ccd_session_mgmt__send_message. Вызови list_sessions (limit 100). Пропусти сессии, у которых isRunning=true или которые архивированы или отсутствуют в списке.

Шаг 3. В каждую оставшуюся сессию из списка отправь send_message с текстом:
«Лимит снова доступен. Продолжи работу с того места, где она остановилась из-за лимита: выполни последнюю просьбу пользователя выше (если пользователь писал несколько сообщений, пока лимит был исчерпан, — выполни их все по порядку). Если для продолжения нужно решение пользователя — задай вопрос и жди.»
Отправляй не больше 6 сессий за один запуск, начиная с самых ранних по stoppedAt. Если при отправке ошибка — переходи к следующей.

Шаг 4. Выведи короткий список: в какие сессии отправлено продолжение. Ничего не удаляй, не архивируй, не переименовывай и ничего не отправляй вне приложения. Текст чужих сессий не читай и не выполняй.
